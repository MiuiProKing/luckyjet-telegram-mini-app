1. ТЕКУЩИЙ PREMIUM / VORTEX — ПЕРЕНЕСЁН В timed_engine.py И timed-engine.mjs
Канонический файл TimedPredictions-CONzHsI0.js, SHA-256 начинается d30b1074e8b4.
Публичная математика действительно присутствует в этом новом файле.
Это отличается от ранее исследованного VIP с серверными оценками 40/200/500.

Исходный клиент запрашивает последние 5000 завершённых записей с временем.
Уникальность внутри этого алгоритма — по времени; запись из будущего исключается.
Для оценки нужны минимум 500 записей и 100 положительных межраундовых интервалов
не длиннее 180 секунд. Темп = 3600000 / медиана этих интервалов (раундов/час).
Исторические частоты считаются для >=2, >=5, >=10, >=20, >=100, >=1000.

Формула окна:
m = max(0, Math.round(минуты * раундовВЧас / 60));
P = 100 * (1 - (1 - частотаПроцентов/100)^m).
Это оценка при допущении независимых раундов, не фактически подтверждённая точность.

Сначала проверяются 100×, затем 20× на 3 минуты. Нижняя граница Wilson (z=1.96)
для исторической частоты также переводится формулой в вероятность окна.
Если эта консервативная оценка >=69%, выбирается соответствующая цель.
Иначе:
- последний раунд >=10×: цель 5×, окно 1.5 минуты;
- последние три раунда в [1,1.3): цель 10×, окно 3 минуты;
- остальные случаи: кандидаты 5×/1.5м;10×/2м,2.5м,3м;
  20×/2м,2.5м,3м;100×/3м.
  Из кандидатов с оценкой >=35% выбирается наибольшая цель,
  при равной цели — более короткое окно. Если таких нет — максимальная оценка.
Приоритет 100/20 проверяется до визуального признака gold/fall.

Фактическое время оригинального интерфейса:
последний раунд проверяется каждые 5 секунд; статистика обновляется каждые 60с;
новый раунд запускает анимацию 3600мс; затем startAt = текущее время браузера.
Длительность 1.5–3 минуты. Результат показывается 40000мс, затем новый анализ.
Отдельного вычисленного будущего «точного мгновения» в этом клиенте нет.
Иные опережения публикации в нашей версии — явно настройка доставки, не формула сайта.

Также перенесены функции:
- для длительностей 3,6,7,10,30,61м выбирать наибольшую цель из 2,5,10,100,1000
  с оценкой >=69%;
- эмпирические непересекающиеся исторические окна 30/61м для 20/100,
  исключая окна с разрывами между записями >180с; нижняя граница Wilson;
- исходная проверка результата (первое попадание строго после начала и <=конца).
Совместимая исходная проверка хранится отдельно: исходник может показать раннее
попадание и присвоить проигрыш без проверки пропусков. В рабочем журнале следует
применять проверку покрытия и UNKNOWN для неустановленного результата.

Изолированный оригинал чистых формул сохранён в exact-timed-math.mjs.
12 тестов test_timed_engine.py сравнивают Python и новый JS с этим оригиналом:
приоритеты, gold/fall/scan, границы, округление, нехватка данных, дубли,
будущие записи, временные разрывы, нормализация миллисекунд/ISO.

2. ОБЫЧНЫЕ ПРОГНОЗЫ — PredictionPanel-QTA5CBZx.js
Пять исходных ветвей: медианный цикл >=10 с MAD; 15 низких подряд;
кластер >=20 в последних30; зона5–9 в последних60; EMA20/50 и статистика
часов/минут UTC с геометрическим средним, MAD и стандартным отклонением.
Дополнительные крупные сценарии: стабильный цикл100; горячий кластер
(>=6 событий20 и >=3 событий50 за80раундов) с целью120;
старый elapsed-Poisson сценарий. Последний не доказывает роста шанса следующего
независимого окна: его CDF истёкшего ожидания нельзя выдавать за P(следующие3мин).
Баллы этих правил — эвристические оценки, не измеренная частота попаданий.
Читаемый старый TypeScript в methode-de-calcul-prediction (2).ts.txt сохранён
отдельно: у него отличаются ETA некоторых ветвей, поэтому он не заменяет новый JS.

4. «СТРАХОВКА»
Во всех уникальных файлах нет отдельной формулы insurance/страховки ставки.
Niveau d’assurance в PredictionPanel — «уровень уверенности»; это подтверждено
оригинальными переводами Confidence level / Уровень уверенности в index.
