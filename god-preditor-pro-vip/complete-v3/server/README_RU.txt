GOD COMPLETE V3 — серверная часть

Новая Edge Function: https://stzrirukuxcyalrsstxx.supabase.co/functions/v1/god-complete-v3
POST JSON {"action":"snapshot","zone":"Europe/Kyiv","afterEventId":0}
Заголовки: apikey = публичный publishable-ключ, Authorization = Bearer legacy anon JWT. Секретный service_role существует только в переменной окружения Edge, в клиент не возвращается.

Все вычисления и записи выполняет сервер. Передать свои коэффициенты, окна или исходы через этот API невозможно: неизвестные поля отклоняются. Сайт и бот получают одни и те же неизменяемые ID сигналов. Параллельные обращения защищены транзакционной арендой и поколением, а в БД действует ограничение одного pending-сигнала на канал.

Полная аналитика считает нашу историю из luckyjet_rounds: completed=true, estimated=false, конечный коэффициент>=1 и timestamp<=серверному времени. Возвращает общие частоты, редкие события, группы UTC/EuropeKyiv, полные медианы/MAD для10/20/40/50/100/200/500. Кеш60секунд. Клиенту не нужно загружать все200000+ строк для календарной статистики.

SQL-таблицы:
- god_complete_v3_signals: ID/channel/target/start/end/issued_at/metadata неизменяемые; только исходы и подтверждения дополняются.
- god_complete_v3_events: последовательный append-only журнал created/hit/miss/unknown/revision. Каждое событие содержит полный сигнал; бот восстанавливается по afterEventId, а не по последним100строкам.
- god_complete_v3_analytics_cache: общая проверенная статистика по часовому поясу.
- god_complete_v3_private.runtime: недоступная клиенту аренда, маленькое состояние моделей, паузы и диагностика.

Анонимным клиентам разрешено только SELECT публичных журналов/кеша и чтение кешированной аналитики. INSERT/UPDATE/DELETE сигналов и событий запрещены. Все новые SQL-функции SECURITY INVOKER, записывающие RPC доступны только service_role. Сигналы и события защищены также триггерами неизменяемости.

Проверка исходов выполняется по всей серверной истории, в том числе за пределами последних5000. Временные HIT подтверждаются фактическим раундом внутри закрывшегося окна. MISS требует покрытия границ и отсутствия большого временного разрыва; иначе UNKNOWN с последующей дозагрузкой. Для N-раундов порядок означает первые N полученных точных завершённых записей, а не доказанную непрерывную последовательность провайдера. Известное попадание в этом полученном префиксе учитывается; отрицательный исход при разрыве не объявляется проигрышем.

В ответе: serverNow/sourceFresh/sourceCutoff/sampleSize; rounds=последние100; analytics=полная история; signals=все активные+последние100; diagnostics=отчёт всех моделей; state=пауза/поглощение; statistics=счётчики ВСЕХ созданных серверных окон, events/cursor/hasMore=постраничный полный журнал. Не вычисляйте долю попаданий по последним100 вместо statistics.

Для фоновой работы создан ОТДЕЛЬНЫЙ pg_cron job god-complete-v3-canonical-tick каждые15секунд через pg_net. В нём используются только публичные anon/publishable данные, не service_role. Прежние12заданий не менялись. Heartbeat работает даже при закрытых сайте и боте.

Горячая Edge-выборка5000 хранится в памяти процесса, полное обновление раз в60секунд; между ними запрашиваются100последних. В БД не переписывается мегабайт5000строк на каждый5секундный тик. Ответы сжимаются gzip при поддержке клиентом.

Выполнено: реальный HTTP200; RLS/права проверены; четыре параллельных обращения HTTP200, дубликатов pending нет; SQL-фикстуры в ROLLBACK подтвердили старое попадание вне head5000, наблюдаемое N-попадание с разрывом и UNKNOWN вместо ложного отрицательного исхода. Исходные коэффициенты, BeeAI и старые версии не удалялись.
